Rules that say what
they'll get wrong.

Every rule here ships with the thing most rule repositories leave out: the false positives it will generate, how to tune them without deleting the detection, and the criteria for escalating a hit. Each one opens into its own write-up.

Sigma

5 rules · host telemetry

  • Shadow copy deletionNear-zero baseline, and near-universal across ransomware families. Six command variants covered. SigmaT1490
  • PPID spoofingCatches the implausible parent/child pairing rather than the spoofing call itself. SigmaT1134.004
  • LSASS memory accessMatches the access mask, not the tool name, so renaming the binary does not help. SigmaT1003.001
  • WMI lateral movementKeys on the WmiPrvSE parent, which is structural. SCCM needs filtering first. SigmaT1047 · T1021.003
  • DLL search-order hijackThree conditions that are common alone and rare together. The hardest of the ten to tune. SigmaT1574.001

KQL

  • Disabled-account authenticationSubStatus 0xC0000072 separates disabled accounts from ordinary logon failures. KQLT1078
  • Service account RDP logonBaseline is essentially zero, so any hit is meaningful on its own. KQLT1021.001
  • Password sprayingCounts distinct users per source — the pivot that per-account alerting misses. KQLT1110.003

How these are written

  1. Behaviour, not artifactsA renamed file should not break a rule. Where possible the detection keys on something structural the attacker cannot choose.
  2. False positives stated up frontEach rule names what will trigger it benignly, and how to exclude that without creating a hole.
  3. Tuning that keeps the detectionExclusions are scoped to an account and a parent together, never to the command alone — the command is what you are trying to catch.
  4. Escalation criteriaA table of findings and the call each one warrants, so a Tier 1 analyst does not have to improvise at 3am.
  5. A way to test itHow to make the rule fire in a lab, and what to check in the resulting event.
A rule without its false positives written down is not finished. It is just a search someone else has to debug at 3am.

These rules come out of the investigations. Signal strength is my own estimate of how cleanly a rule separates true from false positives in a baselined environment: four bars means near-zero false positives, two means it needs real tuning work first.
